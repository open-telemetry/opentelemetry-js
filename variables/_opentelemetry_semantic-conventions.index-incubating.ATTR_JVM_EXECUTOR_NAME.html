    Variable ATTR_JVM_EXECUTOR_NAMEConst Experimental

    ATTR_JVM_EXECUTOR_NAME: "jvm.executor.name" = ...

    Name of the executor.

    Example

    pool-1-thread-*

    Example

    ForkJoinPool.commonPool-worker-*

    Example

    orders-vt-*

    Note

    The executor name SHOULD be low-cardinality. If jvm.executor.owner.name is present, the combination of jvm.executor.owner.name and jvm.executor.name SHOULD be unique within the instrumented application; otherwise, jvm.executor.name SHOULD be unique when an executor-specific name is available. If the executor implementation does not provide an explicit name, instrumentation SHOULD derive a name from available implementation-specific metadata, such as a normalized worker thread name. If no executor-specific name or metadata is available, instrumentation MAY use unknown. The unknown value does not identify an executor, and metrics from multiple executors using this value MAY be aggregated. Users requiring per-executor metric series SHOULD configure a distinct name through the executor's ThreadFactory. Instrumentations SHOULD document how the name is derived and how users can configure it. Once metric series registration for an executor has started, jvm.executor.name and jvm.executor.owner.name MUST remain stable for the lifetime of that registration. Instrumentations SHOULD determine these attributes before the first worker is registered. Instrumentations MUST NOT re-register cumulative metrics under a new attribute set or replay prior cumulative values under new attributes.

    This attribute is experimental and is subject to breaking changes in minor releases of @opentelemetry/semantic-conventions.
